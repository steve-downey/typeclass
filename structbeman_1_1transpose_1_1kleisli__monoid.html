Detailed Description

template<class MONAD_OBJECT, class A>
struct beman::transpose::kleisli_monoid< MONAD_OBJECT, A >

The Kleisli endomorphism monoid of MONAD_OBJECT at A: an instance over Kleisli arrows A -> M<A>, type-erased through std::function so that combine can return the same type it takes – the same erasure detail::left_compose_monoid (fold.hpp) uses for the same reason: a monoid's value type must close under combine, and a bare lambda type does not.

Identity is pure, combine is Kleisli composition (>=>). The Kleisli-form monad laws – pure is the two-sided unit of >=>, and >=> is associative – are exactly this monoid's laws, which is the whole reason to name the instance: it is the value-level statement of "a monad is a monoid in the category of endofunctors", the only form of that statement this library can make.

The monad object is held, not constructed: d_monad is the object every pure and kleisli goes through, so a caller's object that carries state – an allocator, a scheduler, a log – is the one consulted, as it is when passed to traverse. [[no_unique_address]] keeps an empty object free.

The arrows identity and combine return capture a copy of d_monad, not this: an arrow outlives the monoid that built it. combine invokes kleisli on that copy when the arrow is called, rather than storing the result of kleisli(...). derive_monad<Impl>::kleisli's derived branch returns a composition that holds a reference to the object it was called on, and calling it on a copy captured in the arrow keeps that object alive for exactly as long as the arrow is.
