struct beman::transpose::lifted_monoid< APPLICATIVE_OBJECT, CONTEXT, ELEMENT_MONOID >

CONTEXT (e.g.

std::optional<int>) as a monoid, lifted from an instance ELEMENT_MONOID over its element type through an APPLICATIVE_OBJECT over CONTEXT: identity is pure(identity_A), combine is invoke(combine_A, ·, ·). The element instance defaults to the registered Monoid of the element type and is held by value, so a lift of std::optional<int> under addition is spelled lifted_monoid<std::remove_cvref_t<decltype(applicative<std::optional<int>>)>, std::optional<int>, sum_monoid<int>> – the context stays std::optional<int>, unwrapped. The instance's own class is an implementation detail; reach it through the lookup.

Uses invoke, not ap: invoke is the interface that works for every context, including one that cannot hold a callable (apply.hpp's "Applicative pattern invariants" block), whereas ap requires the context to be able to hold the (curried) combining function.

The applicative object is held too, after the element instance so that lifted_monoid<...>{element} still initializes the element instance, and for the reason kleisli_monoid holds its monad object: a caller's stateful object is the one consulted.
